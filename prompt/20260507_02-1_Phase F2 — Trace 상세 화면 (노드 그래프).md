## 사용자 결정 사항 (변경 금지)

### 차별화 핵심 (mockup 그대로)

기존 APM 도구들은 trace를 gantt chart로 그림. ApiLens는 다름:
- 노드 그래프 (React Flow + dagre 자동 left-right 레이아웃)
- 시간 흐름은 왼쪽=시작점(브라우저), 오른쪽=DB/외부 API
- 수직 레이아웃 절대 금지 (사용자 명시 결정)
- 노드 색상 = 종류 (browser/service/db/external)
- 노드 클릭 → 우측 패널에 attributes + payload (lazy load)
- error span은 빨간 강조 + stack trace 즉시 표시

이번 v0.1엔:
- 정적 그래프 (양방향 애니메이션은 v0.2)
- 단일 서비스만 (MSA 박스 분리는 v0.3)
- 노드 펼침/접기 없음 (span 50개 미만 가정)
- 마스킹 룰 GUI 없음 (v0.2)

## 화면 명세

### Layout
경로: /traces/:traceId
```
┌─────────────────────────────────────────────────────────┐
│ ← back   POST /users   3 spans · 109ms · OK             │  헤더
├─────────────────────────────────────────────────────────┤
│                                                          │
│   [노드 그래프 영역]                                      │
│   왼쪽-오른쪽 방향 자동 레이아웃                           │
│   pan/zoom 가능                                          │
│                                                          │
├─────────────────────────────────────────────────────────┤
│ 범례: ● service  ● db  ● external                        │
└─────────────────────────────────────────────────────────┘
┌────────────────┐
│ Selected:      │ ← 노드 클릭 시
│ UserService... │   우측 sidebar
│                │
│ Duration: 95ms │
│ Status: OK     │
│                │
│ Attributes     │
│ ─ http.method  │
│ ─ http.url     │
│                │
│ Payload IN ▼   │
│ {              │
│   "name":...   │
│ }              │
│ Payload OUT ▶  │
└────────────────┘
```

### 헤더
- 좌측: ← back (Dashboard로) + rootOperation (TraceList의 shortenOperation 재사용)
- 우측: spanCount · durationMs · status (mockup의 "3 spans · 109ms · OK" 형태)
- Status가 ERROR면 ERR 빨간 배지

### 노드 그래프
- React Flow + dagre 자동 layout
- direction: 'LR' (left-right)
- 노드: 평면 spans 배열을 트리로 변환 (parentSpanId)
- 엣지: parent → child 화살표

노드 디자인 (커스텀 노드 컴포넌트):
- 원형 또는 둥근 박스
- 색상: spanKind 기준
  - SERVER, INTERNAL → span-server (#1D9E75)
  - DB → span-db (#378ADD)
  - CLIENT → span-external (#EF9F27)
  - UI_EVENT → span-client (#7F77DD)
- 라벨: shortenOperation(operationName)
- error span (status==='ERROR'): 색상은 그대로 + 빨간 ring (border-2 border-status-error) + 살짝 더 큰 크기
- 선택된 노드: 파란 ring (Tailwind ring-2 ring-blue-500)
- 노드 크기는 일정 (mockup처럼 duration 비례 안 함 — 사용자 결정: "각 노드가 얼마나 걸렸는지는 중요하지 않다")

엣지:
- 회색 화살표 (Tailwind stone-400 또는 #888780)
- 부드러운 곡선 (smoothstep)
- error span으로 가는 엣지는 빨간색 (선택)

상호작용:
- 노드 클릭 → 우측 sidebar 토글 + 그 span 하이라이트
- 그래프 영역 클릭 → 선택 해제
- 마우스 휠 zoom, 드래그 pan
- 미니맵 (선택, mockup엔 없으니 일단 생략)

빈 상태:
- spans 0개: "No spans in this trace" (이건 거의 안 일어남, agent가 root span 못 잡으면 이런 경우)

### 우측 Sidebar (Selected Span Panel)
선택된 노드가 없을 땐 안 보임 (또는 "select a node" placeholder).

선택 시:
- 헤더: operationName (mono, 짧게) + duration · status
- error 시: 빨간 배경 + stack trace 박스 (attributes.exception.message + exception.stacktrace)
- attributes 섹션: 키-값 리스트 (mono, 작은 글씨)
  - HTTP: http.method, http.url, http.status_code, http.route
  - DB: db.statement (mono, 줄바꿈 보존)
  - Code: code.namespace, code.function
- Payload IN/OUT 섹션 (collapsible, 기본 IN 펼침/OUT 접힘)
  - lazy load: 노드 처음 클릭 시 GET /v1/traces/{traceId}/spans/{spanId}/payloads
  - 로딩 중: skeleton
  - body가 JSON이면 pretty print + 마스킹 표시 (mockup의 "masked: ssn" 배지)
  - body가 너무 길면 (5KB 초과) "더 보기" 토글
  - body 없으면: "No payload" placeholder (404 아니라 200 with empty array)

마스킹 표시 (mockup 그대로):
- 마스킹된 필드는 회색 톤 + 옆에 작은 배지
- 배지 텍스트: 어느 룰로 가렸는지. 단 v0.1 server 응답에 마스킹 룰 정보가 별도로 안 옴
- 현재 server 응답은 마스킹 적용된 body만 줌 (어떤 룰인지는 없음)
- 따라서 v0.1엔 단순히 "***" 또는 부분 가린 값을 그대로 표시. "masked: ssn" 같은 라벨은 v0.2에서 server response에 maskedFields 필드 추가 후

이 부분만 mockup과 살짝 다름 — v0.2 backlog.

## 데이터 페치 패턴

```typescript
// src/pages/TraceDetail.tsx
const { traceId } = useParams<{ traceId: string }>()

const { data: trace, isLoading, error } = useQuery({
  queryKey: ['trace', traceId],
  queryFn: () => getTrace(traceId!),
  enabled: !!traceId,
  staleTime: 60_000,  // trace는 immutable이라 길게
})

const [selectedSpanId, setSelectedSpanId] = useState<string | null>(null)

// payload는 selected 시점에 별도 query
const { data: payloads, isLoading: payloadsLoading } = useQuery({
  queryKey: ['payloads', traceId, selectedSpanId],
  queryFn: () => getPayloads(traceId!, selectedSpanId!),
  enabled: !!traceId && !!selectedSpanId,
  staleTime: 60_000,
})
```

queryKey 분리 핵심 — trace 자체는 한 번만 페치, payload만 노드 클릭마다 새 페치.
TanStack Query 캐시가 같은 span 두 번 클릭 시 fetch 안 함.

## dagre 레이아웃

```typescript
// src/components/TraceGraph/layout.ts
import dagre from 'dagre'

export function computeLayout(spans: Span[]): { nodes, edges } {
  const g = new dagre.graphlib.Graph()
  g.setDefaultEdgeLabel(() => ({}))
  g.setGraph({ rankdir: 'LR', nodesep: 40, ranksep: 80 })

  const NODE_W = 180
  const NODE_H = 60
  spans.forEach(s => g.setNode(s.spanId, { width: NODE_W, height: NODE_H }))
  spans.filter(s => s.parentSpanId).forEach(s =>
    g.setEdge(s.parentSpanId!, s.spanId)
  )

  dagre.layout(g)

  const nodes = spans.map(s => {
    const { x, y } = g.node(s.spanId)
    return {
      id: s.spanId,
      type: 'span',  // 커스텀 노드 타입
      position: { x: x - NODE_W / 2, y: y - NODE_H / 2 },
      data: { span: s },
    }
  })

  const edges = spans
    .filter(s => s.parentSpanId)
    .map(s => ({
      id: `${s.parentSpanId}-${s.spanId}`,
      source: s.parentSpanId!,
      target: s.spanId,
      type: 'smoothstep',
      style: { stroke: s.status === 'ERROR' ? '#E24B4A' : '#888780' },
    }))

  return { nodes, edges }
}
```
