Phase F1 후속 #2 — Live 모드 시간 윈도우 슬라이딩 fix

## 문제
Dashboard에서 Live 토글 ON 상태에서 5초마다 GET /v1/traces 호출되지만 since/until이
고정값이라 새로 들어온 trace가 시간 윈도우 밖으로 벗어나면 영원히 안 보임.
- 21:42에 dashboard 열고 Last 10 min 선택 → since=21:32, until=21:42 박힘
- 21:49에 새 trace 들어와도 윈도우 밖이라 안 보임
- F5 새로고침하면 since/until이 새로 계산되어 보임

## 진짜 원인
Dashboard.tsx의 시간 범위 계산이 컴포넌트 mount 시 또는 range 변경 시에만 일어남.
useQuery의 refetchInterval은 같은 queryKey + queryFn 클로저 캡처라 호출마다 같은
since/until 사용.

## 수정

위치: apilens-ui/src/pages/Dashboard.tsx

queryFn 안에서 매번 시간 계산:
- Live ON: until = Date.now() — 매 호출마다 슬라이딩 윈도우
- Live OFF: until = 사용자가 range 선택했던 시점 (pinned)

구현 방향:
- pinnedUntil을 useState로 들고 있기
- range 변경 또는 Live OFF로 토글될 때 pinnedUntil = Date.now()로 업데이트
- Live ON이면 queryFn 안에서 Date.now() 사용, OFF면 pinnedUntil 사용
- since는 둘 다 until - rangeToMs(range)

queryKey에 시간을 직접 넣지 말 것 — 매 호출마다 키 바뀌면 캐시 의미 없음.
queryKey는 [service, range, live] 정도. live가 바뀌면 자동 refetch 트리거됨 (의도됨).

## 검증
- 단위 테스트 1개: 시간 계산 헬퍼를 lib/time.ts로 분리 후 Live ON/OFF 분기 테스트
- 사용자 검증:
  1. Dashboard 열고 Live OFF 상태에서 trace 발생 → 5초 기다려도 새 점 안 뜸 (의도됨)
  2. Live ON으로 토글 → 즉시 한 번 refetch + 새 점 보임
  3. Live ON 상태로 5초 기다리며 다른 터미널에서 trace 발생 → 5초 안에 새 점 자동 추가
  4. range를 Last 1 hour로 변경 → since/until 새로 계산 + 즉시 refetch
