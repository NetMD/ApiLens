Phase F1 — UI 프로젝트 셋업 + 대시보드

## 컨텍스트
CLAUDE.md를 먼저 읽고 시작. Backend 완료 상태 (Phase A~E2, 105 tests).
서버는 4개 query endpoint 제공:
  GET /v1/traces?service=&since=&until=&status=&limit=&cursor=
  GET /v1/traces/{traceId}
  GET /v1/traces/{traceId}/spans/{spanId}/payloads
  GET /v1/services
docs/api.md, docs/otel-attributes.md를 정확한 응답 모양 참조용으로 읽을 것.

이번 phase는 UI의 "프로젝트 셋업 + 대시보드 화면"까지. trace 상세 (노드 그래프)는
Phase F2로 분리. F1만 끝나도 운영자가 "트래픽 모니터링되네" 가치는 잡힘.

## F1 화면 명세 — 대시보드

위에서 그렸던 mockup 한 번 더 정리:

### 헤더 (얇게)
- 좌측: ApiLens 로고 (텍스트로 충분, "A" 박스 + "ApiLens")
- 우측: 서비스 셀렉터 + 시간 범위 셀렉터 + Live 토글

### 서비스 셀렉터
- GET /v1/services 응답으로 채움
- 기본 선택: 첫 번째 서비스 (또는 URL ?service= param)
- 변경 시 URL param 업데이트 (브라우저 새로고침해도 유지)

### 시간 범위 셀렉터
- 옵션: "Last 10 min", "Last 1 hour", "Last 24 hours", "Last 7 days"
- 기본: "Last 10 min"
- 변경 시 since/until 계산해서 GET /v1/traces 호출

### Live 토글
- ON: TanStack Query의 refetchInterval 5초
- OFF: 수동 refresh
- 토글 상태는 URL param으로 유지 (?live=true)

### 메인: Latency Scatter
Recharts ScatterChart.
- X축: 시간 (epoch ms → 시간:분 포맷)
- Y축: duration_ms (log scale 옵션. 기본 log)
- 각 점 = trace 1개
- 색상: status === "OK" ? gray : status === "ERROR" ? red : 1초 초과면 amber, 정상이면 gray
- 점 크기: 일정 (3px). 너무 작으면 클릭 어려우니 4~5px
- 호버 시 tooltip: rootOperation, duration, status
- 클릭 시 navigate(`/traces/${traceId}`) — F2 화면으로 (지금은 placeholder)

mockup 색깔 (Tailwind에서):
- 정상 회색: text-stone-500 또는 #888780
- slow 호박: amber-600 #BA7517
- error 빨강: red-500 #E24B4A

### 하단: Recent Traces List
같은 데이터에서 시간 역순 최대 10개:
- 시각 (HH:MM:SS) — 작게
- root_operation — 모노스페이스
- duration_ms — 우측 정렬, error면 빨강
- 상태 배지 (OK/ERR)
- 행 클릭 시 trace 상세로 navigate
- 산점도와 hover 동기화 (선택 — 시간 남으면)

### 빈 상태
- 서비스 없음: "No traces yet. Run your app with -javaagent: ..."
  명령 한 줄 보여주기 (운영자가 처음 깔았을 때 막히지 말라고)
- 서비스는 있는데 시간 범위 trace 없음: "No traces in selected time range"

## 데이터 페치 패턴

```typescript
// src/api/traces.ts
export async function listTraces(params: ListTracesParams): Promise<TracesResponse> {
  const url = new URL(`${BASE_URL}/v1/traces`)
  if (params.service) url.searchParams.set('service', params.service)
  // ...
  const res = await fetch(url, { headers: { Accept: 'application/json' } })
  if (!res.ok) throw new ApiError(res.status, await res.text())
  return res.json()
}

// src/pages/Dashboard.tsx
const { data, isLoading, error } = useQuery({
  queryKey: ['traces', { service, since, until }],
  queryFn: () => listTraces({ service, since, until, limit: 100 }),
  refetchInterval: live ? 5000 : false,
})
```

cursor 페이지네이션은 F1에서 안 씀 (대시보드는 limit=100으로 충분).
F2의 trace 상세에서도 cursor 안 써. v0.2의 "전체 trace 검색" 화면에서 사용.

## 타입 (src/types/api.ts)

server 응답 모양에 정확히 맞춤. docs/api.md 참조.

```typescript
export type SpanKind = 'SERVER' | 'CLIENT' | 'INTERNAL' | 'DB' | 'UI_EVENT'
export type SpanStatus = 'OK' | 'ERROR'

export interface TraceSummary {
  traceId: string
  rootOperation: string
  serviceName: string
  startTime: number       // epoch ms
  durationMs: number
  status: SpanStatus
  spanCount: number
  hasError: boolean
}

export interface TracesResponse {
  traces: TraceSummary[]
  nextCursor: string | null
}

export interface ServiceInfo {
  name: string
  traceCount: number
  lastSeen: number
}

export interface ServicesResponse {
  services: ServiceInfo[]
}

// SpanDto, PayloadDto 등은 F2에서 추가
```

## 응답 시 server proxy 설정

vite.config.ts:

```typescript
import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'

export default defineConfig({
  plugins: [react()],
  server: {
    port: 5173,
    proxy: {
      '/v1': {
        target: 'http://localhost:8765',
        changeOrigin: true,
      },
    },
  },
  build: {
    outDir: 'dist',
    emptyOutDir: true,
  },
})
```

역시 빈 문자열로 충분.

## 검증 (사용자가 수행)

너는 코드 작성만. 사용자가 실제 동작 검증.

검증 절차:
1. cd apilens-ui && npm install
2. (다른 터미널) ./gradlew :apilens-server:bootRun
3. cd examples/sample-app && ./gradlew bootRun (-javaagent: 옵션 적용)
4. POST /api/users 몇 번 호출해서 trace 데이터 만들기
5. cd apilens-ui && npm run dev
6. 브라우저 http://localhost:5173 열기

체크리스트:
[ ] 헤더에 서비스 셀렉터 보임 ("sample-app" 등)
[ ] 시간 범위 셀렉터 동작 (Last 10 min 등)
[ ] Live 토글 ON 시 5초마다 refetch (네트워크 탭에서 확인)
[ ] 산점도에 점들 표시
[ ] 점 호버 시 tooltip (rootOperation, duration, status)
[ ] 점 클릭 시 /traces/{id} 로 이동 (placeholder 페이지여도 OK)
[ ] 하단 recent traces list 동기화 (같은 데이터 시간 역순)
[ ] error trace는 빨간 점으로 구분
[ ] 1초 초과 trace는 amber로 구분
[ ] URL ?service= ?live= param 동작 (새로고침해도 유지)
[ ] 빈 상태 (trace 0개) 시 도움말 메시지

production 빌드 검증:
7. cd apilens-ui && npm run build
8. ls -la dist/  -- 산출물 확인
9. ./gradlew :apilens-server:bootJar
10. java -jar apilens-server/build/libs/apilens-server-0.1.0-SNAPSHOT.jar
11. 브라우저 http://localhost:8765 -- 같은 포트에서 UI 보여야 함
12. 단일 jar로 동작 확인되면 v0.1의 배포 모양 검증 완료

## 주의사항

- 디자인은 mockup의 단순함 유지. 화려한 효과 추가 금지.
- 운영자 페르소나: 새벽에 깬 사람. 정보 밀도 적당, 시각적 노이즈 최소.
- mockup 색깔 정확히 따라가기 (위 Tailwind config).
- TypeScript strict mode. `any` 금지.
- console.log 흔적 남기지 말 것 (production에서 운영자 노이즈).
- "테스트 통과" 단정 보고 금지. 너의 작업 범위는 코드 작성과 (가능하면)
  npm run build 통과까지. 동작 검증은 사용자가 위 절차로 수행.
