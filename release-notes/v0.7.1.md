## ApiLens v0.7.1 — 안 쓰는 SQL 원문 되찾기 | Reclaim unreferenced SQL statements

**collector(server) 만 바뀌는 릴리스입니다. agent 를 다시 배포할 필요가 없습니다.** 어느 흐름도 더 안
가리키게 된 SQL 원문을 밤 정리와 「전체 삭제」에서 되찾습니다. 본문 정리의 상한도 「몇 번 도는가」에서
「몇 초 동안 도는가」로 바꿔, 정리가 길어져 수신을 막는 일이 없게 했습니다. 밖으로 나가는 응답과 화면에
보이는 값은 **이전과 같습니다**.

**DB 스키마는 바뀌지 않습니다** — 직전 버전과 달리 마이그레이션이 없어, 되돌리려면 이전 jar 로 바꾸기만
하면 됩니다. 백업을 복원할 필요가 없습니다.

**This release changes only the collector (server) — you do not need to redeploy the agent.** SQL statements
that no trace points to any more are now reclaimed by the nightly cleanup and by "delete everything". The
payload-body cleanup is now bounded by **time** instead of by a round count, so a long cleanup can no longer
block ingest. API responses and everything you see on screen stay the same. **No database migration is
included in this release** — rolling back is just swapping the jar, with no backup to restore.

---

### 새로운 기능 | What's new

- **어느 흐름도 더 안 가리키게 된 SQL 원문을 되찾습니다** — 밤 정리와 「전체 삭제」 둘 다에서 돕니다.
  참조가 남아 있는 원문은 그대로 남으므로, 이 표는 지금 보관 중인 기록이 쓰는 SQL 의 **종류 수만큼**
  남습니다(바이트가 아니라 종류 수입니다). 몇 종류를 되찾았는지와 걸린 시간이 수집기 로그에 한 줄
  남습니다 — 되찾은 것이 0 종이어도 남습니다.

  ```
  sql statement gc start: batchSize=500 budgetMs=8000
  sql statement gc scan: scanMs={훑는 데 걸린 시간} reclaimable={되찾을 수 있는 종류 수} watermarkRowid={표시점}
  sql statement gc: deleted={지운 종류 수} rounds={회전 수} elapsedMs={걸린 시간}
  ```

  - **형식이 깨진 span 속성이 한 건이라도 있으면 그 실행은 한 행도 지우지 않고 통째로 건너뜁니다**
    (`sql statement gc skipped:` 경고 한 줄). 살아 있는 참조를 끊지 않기 위한 보수적 선택입니다.
    지운 것이 없다는 뜻의 `deleted=0` 과는 **다른 줄**이니 구분해서 읽으세요.
  - 이 실행은 **정해진 시간 안에서만** 돕니다(기본 8초). 다 못 지우면 남은 몫은 다음 밤이 이어서
    합니다 — **실패가 아닙니다.**
  - 화면의 [전체 삭제] 안내문에도 무엇이 함께 지워지는지 「SQL 원문」 한 낱말을 더했습니다.

- **수집기 로그를 30일 보관합니다** (이전 7일). 문제가 생긴 밤의 로그를 한 달 뒤에도 열어 볼 수 있습니다.

### 바뀐 것 | Changed

- **본문 정리의 상한이 「몇 번 도는가」에서 「몇 초 동안 도는가」로 바뀌었습니다** (기본 30초). 회전 수는
  한 회전이 얼마나 걸릴지 알 수 없어 정리가 길어지는 것을 막지 못했습니다. 회전 수 상한은 **두 번째
  안전망으로 남겨** 뒀습니다. 시작 로그에 남던 기존 값은 그대로이고 새 값(`budgetMs=`)이 뒤에 붙습니다.
  요약 줄의 모양은 **바뀌지 않았습니다**.

  ```
  payload body gc start: batchSize=1000 maxRounds=5000 budgetMs=30000
  ```

- **명세 화면(`/swagger-ui`)에 공통 오류 응답이 보입니다.** 서버가 실제로 내려주는 응답은
  **그대로입니다** — 문서에 보이는 모양만 정리했습니다.
- **버전 0.7.0 → 0.7.1** (collector jar). 화면 왼쪽 위 버전 라벨은 `v0.7` **그대로**입니다 — 앞 두
  자리만 표시하므로 이번에는 안 바뀝니다. **agent 버전도 `0.6.0` 그대로**입니다.

### 고친 것 | Fixed

- **브라우저 탭 아이콘이 생겼습니다.** 지금까지는 탭 아이콘을 요청할 때마다 서버가 404 를 돌려줬습니다.
- **숫자와 단위가 좁은 화면에서 갈라지지 않습니다** — `1.2` 와 `GB` 가 줄이 바뀌며 떨어지던 것을
  고쳤습니다.
- **대시보드가 뜨는 동안 보이는 자리 표시의 높이가 실물과 맞습니다.** 로딩이 끝날 때 화면이 튀지
  않습니다.
- **설치 마법사 2단계의 서비스 이름 예시를 일반 예시로 바꿨습니다** (`my-api, order-service`).
- **계측 라이브러리가 음수 시간을 받을 때 내는 경고 한 갈래를 더 걸러냅니다** — 시계가 거꾸로 갈 때
  쏟아지던 잡음의 나머지 절반입니다. **로그 레벨은 안 건드렸습니다**: 같은 로거의 다른 경고는 그대로
  보입니다.
- **수집기 안 주석과 실제 설정값이 어긋나 있던 자리를 맞췄습니다.** 동작은 바뀌지 않습니다.

### 보안 | Security

- **인증 면제 경로 판정이 좁아졌습니다** — 경로에 `%` 가 들어 있으면 면제하지 않고 인증을 요구합니다.
  평범한 설치 마법사 경로와 화면 자원은 **그대로 면제됩니다**.
- **설치 마법사 입력에 상한이 생겼습니다** — 서비스 목록은 50개까지이고, 수집기 주소는 호스트가 있어야
  합니다. 빈 값과 값 없음이 통과하던 기존 동작은 **그대로입니다**.
- **출고 자동화 스크립트에서 값이 명령으로 섞여 들어갈 수 있던 자리 한 곳을 막았습니다.** 같은 모양이
  다시 생기지 않도록 자동 검사 한 단계를 함께 넣었습니다.
- **화면이 쓰는 라우터 라이브러리를 올렸습니다** (`react-router` `7.15` → `7.18`). 올린 뒤
  `npm audit` 에서 이 항목이 사라졌습니다.

### 주의 | Notes

- **「전체 삭제」는 수신을 멈춘 상태에서 누르고, 밤 정리 시간(기본 04:00)은 피하세요.** 위의 SQL 원문
  회수가 도는 동안 「전체 삭제」가 겹치면, 그 몇 초 사이에 새로 들어온 흐름 수십 건의 SQL 원문이 상세
  화면에서 잠시 안 보일 수 있습니다. **기록 자체는 하나도 잃지 않고**, 같은 SQL 이 다시 들어오면 저절로
  복구됩니다. 겹치는 갈래를 코드에서 막는 보완은 **아직 들어 있지 않아**, 이 운영 규칙으로 피합니다.
- **되찾는 양은 「서로 다른 SQL 이 얼마나 늘어나는가」에 달려 있습니다.** 앱이 문자열을 이어 붙여 SQL 을
  만들면(`IN (?,?,?)` 의 물음표 개수가 매번 다른 형태 등) 종류가 계속 늘고, 그만큼 되찾을 몫도 커집니다.
  **이 릴리스는 줄어드는 비율을 약속하지 않습니다** — 각자의 환경에서 재 보셔야 합니다.
  - 참고로 **이 프로젝트의 운영 환경에서 측정 시**(2026-09-14 23:28 · 운영 DB 를 읽기 전용으로 조회),
    SQL 원문은 전체 **527 종**이었고 그중 **아무 기록도 안 가리키는 것이 335 종**이었습니다. 배포가
    없던 8일 동안 하루 약 50 종씩 늘어난 값입니다. **이 숫자는 그 시점에 쌓여 있던 것을 잰 것이지, 이
    릴리스가 줄여 주는 양이 아닙니다.**
- **줄어든 양을 견줄 때는 이 버전을 올린 첫 밤 이후 값끼리만 비교하세요.** 그 이전 값과 직접 빼면 회수
  기능이 없던 기간이 섞여 「얼마나 줄었는가」가 아니라 「그동안 얼마나 쌓였는가」를 재게 됩니다.
- **파일 크기가 그날 바로 줄지는 않습니다** — 줄어드는 것은 **새로 들어가는 양**입니다. 이미 쓴 페이지는
  밤 정리와 빈 공간 회수가 평소 속도로 돌려줍니다.

### 업그레이드 | Upgrade

1. **수집기를 정상 종료합니다.**
2. **collector jar 를 교체하고 재기동합니다.** 이 버전은 **DB 스키마를 바꾸지 않습니다** — 마이그레이션이
   없으므로 기동할 때 하는 일이 없습니다. 백업은 평소 습관대로 떠 두면 좋지만, 이번 버전을 올리기 위해
   반드시 필요한 단계는 아닙니다.
3. **agent 는 그대로 두세요** — **다시 배포할 필요가 없고**, 대상 앱 JVM 재시작도 필요 없습니다.
   agent 버전 라벨이 `0.6.0` 으로 계속 보이는 것이 정상입니다.
4. **새 설정 항목이 없습니다** — 설정 파일이나 JVM 옵션을 손댈 필요가 없습니다. 위에 적힌 시간 예산(8초 ·
   30초)과 보관 일수(30일)는 기본값이며 그대로 두면 됩니다.

- **되돌릴 때**: **jar 만 이전 버전으로 바꾸면 됩니다.** 이 버전은 스키마를 바꾸지 않았고 저장 형태도
  그대로라, 백업을 복원할 필요가 없습니다.
- **올릴 때 알아 둘 것 — 적재 입구가 형식이 틀린 `spanId` 를 거부합니다.** 16진수 32자 이하가 아니면
  `400` 입니다. agent `0.6.0` 이 보내는 값은 전부 통과하므로(16진수 16자), **직접 만든 적재 스크립트가
  있을 때만** 확인하세요.
- **API 호환** — 경로·요청·응답에서 삭제되거나 타입이 바뀐 필드가 **0**이고 새 endpoint 도 **0**입니다.
  늘어난 것은 거부되는 입력의 범위와, 명세 화면에 보이는 오류 응답 설명뿐입니다.

> **Collector-only release — no agent redeploy needed, and no database migration.** SQL statements that no
> span refers to any more are now reclaimed, both after the nightly cleanup and after "delete everything".
> The sweep is bounded by time (8 s by default), skips the whole run if it finds a malformed span attribute
> (logged as `sql statement gc skipped:`, which is **not** the same as `deleted=0`), and lets the next night
> continue whatever is left. The payload-body cleanup is now bounded by **time** (30 s) instead of by a round
> count; the round cap stays as a second safety net and the summary log line is unchanged. Collector logs are
> kept for 30 days (was 7). The ingest endpoint now rejects a malformed `spanId` with `400` — hex, 32 chars or
> fewer; agent `0.6.0` sends 16 hex chars, so only hand-rolled ingest scripts are affected. Fixes: the browser
> tab icon (previously a 404), a number/unit line break on narrow screens, dashboard skeleton height, a generic
> service-name example in the setup wizard, one more noisy library warning filtered without touching log
> levels, and a stale in-code comment. Security: auth-exempt paths containing `%` now require a token, setup
> input has bounds (50 services, collector URL must have a host), one command-injection spot in the release
> automation is closed with a guard against regressions, and `react-router` moved to 7.18. Rolling back is
> just swapping the jar — nothing to restore. **One operational rule**: press [전체 삭제] only while ingest is
> paused, and avoid the nightly cleanup window (04:00 by default) — otherwise SQL text for a few dozen traces
> that arrive during those seconds may be missing from the detail view for a while. No trace, span or payload
> is lost, and the text comes back on its own the next time the same statement is ingested.
