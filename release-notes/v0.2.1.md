## ApiLens v0.2.1 — payload 크기 가드 + 수동 데이터 정리 | Payload size guard, manual data cleanup

server-only 유지보수 릴리스입니다. **agent 모듈은 변경 없음** (v0.1/v0.2 agent 그대로 호환), 스키마 변경 0.
대형 payload 를 server 저장 시점에 잘라내는 안전망과, 설정 페이지에서 보관 기간 즉시 적용·전체 삭제를
누르는 수동 정리 API 를 추가했습니다.

A server-only maintenance release. The agent is unchanged. Adds a server-side payload size guard and
manual data-cleanup APIs.

---

### 새로운 기능 | What's new

- **payload 크기 가드 (server-side)** — ingest 저장 직전, 개별 payload body 가 `apilens.ingest.max-payload-bytes`(기본 1MB)를 넘으면 server 가 한도까지 잘라 저장하고 `truncated=true` 로 기록합니다. agent 가 정상 흐름에서 먼저 64KB 로 자르므로 보통은 동작하지 않는 안전망이며, agent 우회·오작동·대형 payload 폭증을 server 저장 시점에 차단합니다. **마스킹 적용 후 측정·절단**(mask → truncate)이라 마스킹을 우회하지 않고, UTF-8 문자 경계를 보존합니다.
- **수동 데이터 정리 API** (`POST /v1/maintenance/cleanup` · `POST /v1/maintenance/purge`) — 설정 페이지 "데이터 관리"에서 보관 기간 즉시 적용 / 전체 삭제를 트리거합니다. `payloads → spans → traces` 순 행 단위 배치 DELETE + PRAGMA 로만 공간을 회수하며 **DB 파일을 삭제/이동/재생성하지 않습니다**. purge 는 되돌릴 수 없습니다(이 버전 시점에는 인증이 없으므로 신뢰 네트워크에만 노출).

### 변경 | Changed

- **ingest 설정 키 이름 교정** — `apilens.ingest.max-batch-size-bytes` → `apilens.ingest.max-payload-bytes`. 옛 키는 읽는 코드가 없던 dead key 였고 실제 정책은 **개별 payload body 한도**입니다. yml 에 옛 키를 적어 둔 환경은 새 키로 바꿔 주세요(안 바꿔도 기본 1MB 로 동작).
- **수동 정리 시 WAL 회수 보강** — `cleanup`/`purge` 후 `incremental_vacuum → wal_checkpoint(TRUNCATE) → ANALYZE` 순서로 `-wal` 파일을 잘라 디스크를 회수합니다. 화면을 보는 중(reader 활성)이면 `wal_checkpoint` 가 부분 실패할 수 있어 `freedBytes` 가 삭제량 대비 작게 나올 수 있습니다(한도이지 결함 아님).
