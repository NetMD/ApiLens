## ApiLens v0.8.0 — 시계에 맞춰 흐르는 대시보드 차트 | A dashboard chart that scrolls with the clock

**주로 collector(server) 와 화면이 바뀌는 릴리스입니다. agent 는 보고하는 버전 번호만 바뀌어, 다시 배포하지 않아도 됩니다.** 대시보드의 Live
차트가 5초마다 통째로 다시 그려지며 건너뛰던 것을, 작업 관리자의 그래프처럼 **종이가 옆으로 흐르듯** 시계에 맞춰
움직이게 바꿨습니다. 밤 정리의 SQL 원문 회수는 [전체 삭제]와 겹친 것을 알아채면 그 회차를 멈춥니다. 설치
마법사는 서버가 거절한 이유를 화면에 보여 줍니다.

**DB 스키마는 바뀌지 않습니다** — 마이그레이션이 없어, 되돌리려면 이전 jar 로 바꾸기만 하면 됩니다. 백업을
복원할 필요가 없습니다. 화면 왼쪽 위 버전 라벨이 **`v0.8`** 로 바뀝니다.

**This release mainly changes the collector (server) and its web UI. The agent only changes the version number it reports, so redeploying it is optional.**
The Live dashboard chart now scrolls with the clock instead of redrawing and jumping every five seconds. The
nightly SQL-statement sweep stops that night's round when it notices an overlap with "delete everything", and
the setup wizard shows the reason the server rejected your input. **No database migration** — rolling back is
just swapping the jar. The version label in the top-left corner now reads **`v0.8`**.

---

### 새로운 기능 | What's new

- **대시보드 Live 차트가 시계에 맞춰 흐릅니다.** 창이 매 순간 왼쪽으로 조금씩 밀리고, 새 점은 오른쪽 끝에서
  흘러 들어옵니다. 5초마다 오는 응답은 새 점을 더하고, 창 전체가 한 번에 건너뛰지 않습니다.
  - **1분 창에서 가장 잘 보입니다.** 5분·10분 창은 **최근 500건까지만** 그립니다 — 한 번에 받아 오는 양의
    서버 상한이 500건이라, 들어오는 양이 많은 시간대에는 창의 왼쪽이 비어 보입니다. 그럴 때는 차트 아래 범례 줄에
    알림이 뜹니다.
  - 흐르는 창(1분·5분·10분)의 차트는 **1초마다 가장 느린 요청 하나와 오류 전부**만 점으로 그립니다. 오류는
    하나도 빠지지 않습니다. 차트 아래 목록은 받은 그대로입니다.
  - 새 점은 약 8초 늦게 나타납니다. 점이 오른쪽 끝에서 갑자기 생기지 않고 흘러
    들어오게 하려고 **일부러 둔 여유**입니다. 점의 가로 자리와 툴팁 시각은 실제 시작 시각 그대로입니다. 오래
    걸린 요청은 걸린 시간만큼 안쪽에서 나타나는 것도 정상입니다.
  - Live 를 켠 동안 세로 축의 위 끝은 10 · 100 · 1,000 ms 처럼 10 의 거듭제곱으로 올려 잡습니다. 흐르는 동안 눈금이 튀지
    않게 하려는 것입니다.
  - 점을 누르고 있는 동안에는 흐름이 잠깐 멈춥니다. 운영체제에서 「동작 줄이기」를 켜 두면 흐르지 않고
    응답이 올 때마다 한 번에 바뀝니다.
  - 1시간 이상 창은 **흐르지 않고**, 지금처럼 응답이 올 때 바뀝니다. 다만 Live 를 켠 1시간 이상
    창도 세로 축의 위 끝이 위 규칙을 따르고, 창의 오른쪽 끝이 약 8초 늦습니다.
  - 점이 나타날 때의 움직임(애니메이션)은 Live 를 끈 화면을 포함해 모든 차트에서 껐습니다. 5초마다 점이
    반짝이던 것을 없애려는 것입니다.

- **Live 를 끄면 차트가 선택한 시간마다 한 칸씩 옆으로 넘어갑니다.** 1분 창이면 1분 동안 멈춰 있다가, 다음 1분
  구간이 다 차면 0.5초 동안 옆으로 부드럽게 밀려 넘어갑니다. 5분·10분·1시간·24시간·7일 창도 같습니다.
  - 창이 끝난 뒤 늦게 도착하는 요청을 기다리려고 3초 여유를 두고 넘깁니다.
  - 운영체제에서 「동작 줄이기」를 켜 두면 밀리지 않고 한 번에 바뀝니다.
  - Live 를 끈 차트의 가로 눈금은 10초·1분·10분처럼 정해진 시각에 붙고, 7일 창은 날짜로 적습니다.

- **대시보드에 [차트 일시 정지] 버튼이 생겼습니다** (Live 스위치 옆). 누르면 차트와 아래 목록이 그 모습 그대로
  멈춥니다. 다시 누르면 지금 시각으로 돌아가 그동안 들어온 요청을 모두 보여 줍니다.
  - Live 를 켠 동안에는 멈춘 사이에도 뒤에서 계속 받아 옵니다.
  - 서비스·시간 범위·Live·필터를 바꾸면 저절로 풀립니다.
  - 수집기가 데이터 받기를 멈추는 「수신 일시정지」와는 다른 기능입니다. 이 버튼은 **화면만** 멈춥니다.

- **설치 마법사가 서버가 거절한 이유를 보여 줍니다.** [완료]나 [건너뛰기]가 `400` 으로 돌아오면, 서버가 보낸
  이유가 버튼 가까이에 한 줄 나옵니다. 이유 문장은 서버가 보낸 **영어 그대로**입니다. 네트워크 오류와 서버
  내부 오류 때의 안내는 이전과 같습니다.

- **파비콘을 PNG 로도 싣습니다** (32×32 · 홈 화면 추가용 180×180). SVG 파비콘을 그리지 않는 브라우저를 위한
  것이고, 기존 SVG 파비콘은 그대로입니다.

### 바뀐 것 | Changed

- **SQL 원문 회수의 회전 줄이 걸린 시간을 세 구간으로 나눠 적습니다** — 연결을 잡고 시작하기까지 · 삭제
  문장 · 마무리(커밋). 본문 정리 회전 줄과 **같은 이름 · 같은 뜻**입니다. 이전 버전의 이 줄에 있던
  `statementMs` 는 회전 전체였고 이제는 삭제 문장 하나입니다. **두 버전의 값을 같은 열에서 견주지 말고, 세
  값의 합으로 견주세요.**
- **SQL 원문 회수가 실패할 때 남기는 줄이 그때까지 지운 수를 말합니다.** 이전 줄은 앞 회전이 이미 지운 뒤에
  실패해도 「아무것도 안 지웠다」고 적었습니다.
- **버전 0.7.1 → 0.8.0** (collector jar · agent jar).
- **agent 가 보고하는 버전이 제품 버전을 따릅니다.** 지금까지는 agent 코드가 마지막으로 바뀐 버전(`0.6.0`)을
  보고해서, jar 는 새것인데 화면에는 옛 번호가 보여 배포가 안 된 것처럼 헷갈렸습니다. 이제 새 agent jar 는
  `0.8.0` 을 보고합니다. 계측 동작은 바뀌지 않았습니다.

### 고친 것 | Fixed

- **밤 정리가 [전체 삭제]와 겹친 것을 알아채면 그 회차의 SQL 원문 회수를 멈추고 다음 밤에 다시 합니다.** 이
  확인은 삭제 문장 안에서 하므로, 확인과 삭제 사이에 틈이 없습니다. 다만 **겹침을 다 막지는 못합니다.** 그래서
  아래 「주의」의 운영 규칙은 **그대로 지켜 주세요.**
- **설치 마법사의 주소 검사가 서버와 같은 기준으로 호스트·포트를 봅니다.** 이전에는 `http://` 접두만 봐서,
  `http://` 만 친 경우 [완료]에서 「잠시 후 다시 시도해 주세요」라는 틀린 안내가 나왔습니다. 이제는 입력 칸
  아래에 무엇이 틀렸는지 나오고 [다음]이 잠깁니다.
- **README 기능 표가 `traceparent` 헤더 전파를 있는 기능처럼 적던 문면을 고쳤습니다.** 지금은 계측된 요청
  흐름의 trace/span ID 형식만 W3C 와 호환되고, 헤더 전파는 로드맵에 있습니다.

### 보안 | Security

- **계측 분석 화면의 요약 로그가 요청에 담긴 서비스 이름을 실을 때 줄바꿈을 걸러 한 줄로 남깁니다.** 줄
  머리말과 필드 이름은 그대로입니다.
- **ApiLens 서버가 설치 마법사에 돌려주는 거절 이유는 미리 정해 둔 고정 문장 7종뿐입니다.** 입력한 값이나 서버
  내부 정보(경로 · 스택 등)는 실리지 않으며, 자동 시험이 이를 지킵니다.

### 주의 | Notes

- **「전체 삭제」는 수신을 멈춘 상태에서 누르고, 밤 정리 시간(기본 04:00)은 피하세요.** 이 규칙은 이번 버전에서도
  바뀌지 않습니다. 겹치면 그 몇 초 사이에 들어온 흐름 수십 건의 SQL 원문이 상세 화면에서 잠시 안 보일 수
  있습니다. 기록 자체는 잃지 않고, 같은 SQL 이 다시 들어오면 저절로 복구됩니다.
- **SQL 원문 회수 로그 읽는 법** — 회수 시작 줄(`sql statement gc start:`)은 있는데 요약 줄
  (`sql statement gc: deleted=…`)이 없으면, 그 실행은 **건너뜀 또는 실패**입니다. 둘은 바로 앞 경고·오류 줄의
  머리말로 가릅니다. **멈춘 회차에는 요약 줄이 있습니다** — 그때는 요약 줄 바로 앞의 경고 줄 머리말로 멈춘
  것을 알 수 있습니다.

### 업그레이드 | Upgrade

1. **수집기를 정상 종료합니다.**
2. **collector jar 를 교체하고 재기동합니다.** 이 버전은 **DB 스키마를 바꾸지 않습니다** — 기동할 때 하는 일이
   없습니다. 백업은 평소 습관대로 떠 두면 좋지만, 이번 버전을 올리기 위해 반드시 필요한 단계는 아닙니다.
3. **agent 는 다시 배포하지 않아도 됩니다** — 계측 동작이 이전과 같습니다. 그대로 두면 agent 버전 라벨이
   `0.6.0` 으로 계속 보입니다. 라벨을 `0.8.0` 으로 맞추고 싶으면 새 agent jar 로 바꾸고 대상 앱을 재시작하세요.
4. **열려 있던 브라우저 탭은 새로고침하세요.** 옛 탭은 `v0.7` 라벨과 옛 차트를 계속 보여 줍니다. 파비콘은
   브라우저가 기억한 옛 그림이 한동안 보일 수 있습니다.
5. **새 설정 항목이 없습니다** — 설정 파일이나 JVM 옵션을 손댈 필요가 없습니다.

- **되돌릴 때**: **jar 만 이전 버전으로 바꾸면 됩니다.** 스키마와 저장 형태가 그대로라 백업을 복원할 필요가
  없습니다.
- **올릴 때 알아 둘 것 — 설치 마법사가 포트가 65535 를 넘는 서버 주소를 거절합니다** (`400`). 설치 건너뛰기도
  같은 주소에서 거절됩니다. TCP 포트는 65535 까지라 그 너머의 주소는 원래 쓸 수 없는 값입니다 — **실제로 쓰던
  주소가 거절되는 경우는 없습니다.** 빈 주소로 설치를 건너뛰는 길은 그대로입니다.
- **API 호환** — 경로 · 요청 · 응답에서 삭제되거나 타입이 바뀐 필드가 **0** 이고, 새 endpoint 도 **0** 입니다.
  늘어난 것은 설치 마법사가 거부하는 주소의 범위뿐입니다.

> **Mainly a collector and UI release — agent redeploy optional, no database migration.** The Live dashboard chart now scrolls
> with the clock; new points flow in from the right edge about 8
> seconds late on purpose, while each point's position and tooltip keep the real start time. It looks best on the
> 1-minute window; the 5- and 10-minute windows draw only the latest 500 traces (the server's per-request cap), so
> the left side can look empty on busy hours and a notice appears in the legend row under the chart. Scrolling windows plot the
> slowest trace per second plus every error; the list under the chart is unchanged. With Live off, the chart now pages
> forward one window at a time: it holds still for the selected range, then slides sideways to the next window over
> half a second (3 seconds after that window closes, so late traces make it in); its time axis ticks sit on round
> times, and the 7-day window shows dates. A new "차트 일시 정지" (pause chart) button next to the Live switch freezes
> the chart and the list; pressing it again jumps to the current time and shows everything that arrived meanwhile. It
> only pauses the screen, unlike the collector's ingest pause. The 1-hour-and-longer windows do not scroll and update when a response arrives, as before; with Live on, the longer windows
> also use the power-of-ten axis top and their right edge lags the same way. Point entry animation is now off on
> every chart, including the Live-off view. The setup wizard now shows the server's rejection reason (in English, as
> sent; the server only ever sends one of seven fixed sentences — never your input or internal paths — and a test
> keeps it that way) and checks host and port the same way the server does. The nightly SQL-statement sweep stops that night's
> round when it notices an overlap with "delete everything" and retries the next night — it cannot catch every
> overlap, so keep pausing ingest before a purge and avoid the 04:00 window. The sweep's round log line now splits
> its time into three parts with the same names as the payload-body sweep; `statementMs` used to be the whole
> round and is now the delete statement alone, so compare the sum of the three values across versions. Its failure
> line now reports how many rows were already deleted. A PNG favicon (32×32, plus a 180×180 home-screen icon) was
> added next to the SVG one. The agent now reports the product version (`0.8.0`) instead of the version its code last
> changed in (`0.6.0`); its instrumentation is unchanged, so redeploy it only if you want the label to match. **One compatibility note**: the setup wizard now rejects a collector URL whose port is
> above 65535 (`400`), including in the skip flow; such ports cannot be used over TCP anyway, and a blank URL still
> skips setup. API paths, request and response fields are unchanged. Rolling back is just swapping the jar.
