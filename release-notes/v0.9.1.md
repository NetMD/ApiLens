## ApiLens v0.9.1 — 밤 정리의 빈 공간 회수를 묶음으로 · 말풍선 고침 · 화면 정비 | Batched nightly space reclaim, tooltip fix and UI polish

**collector(server) 와 화면이 바뀌는 정비 릴리스입니다. agent 코드는 바뀌지 않아 다시 배포하지 않아도 됩니다.**
밤 정리가 빈 공간을 한 페이지씩 따로 돌려주던 것을 **250 페이지씩 묶어** 돌려주고, 한 번에 돌려주는 몫을 5,000 에서
**20,000 페이지**로 늘렸습니다. 차트에서 마우스를 점에서 점으로 곧장 옮기면 말풍선이 앞 점의 내용을 들고 있던 것을
고쳤고, 빨간 오류 알림과 차트 축 글자를 더 또렷하게 바꿨습니다.

**DB 스키마는 바뀌지 않습니다** — 마이그레이션이 없어, 되돌리려면 이전 jar 로 바꾸기만 하면 됩니다. 백업을 복원할
필요가 없습니다. **하위호환을 깨는 변경도 없습니다.** 화면 왼쪽 위 버전 라벨은 **`v0.9` 그대로**입니다 — 판은
`/v3/api-docs` 의 `info.version`(`0.9.1`)으로 확인하세요. **API 키를 설정해 쓰는 설치는 꼭 올리세요.**

**A maintenance release for the collector (server) and its web UI. The agent code is unchanged, so redeploying it is
optional.** The nightly cleanup now returns free pages to the OS in **batches of 250 pages** instead of one page at a
time, and its per-night share grows from 5,000 to **20,000 pages**. The chart tooltip no longer keeps the previous
point's content when the mouse jumps straight to another point, and the red error toast and the chart axis labels are
easier to read. **No database migration and no breaking change** — rolling back is just swapping the jar. The version
label in the top-left corner **stays `v0.9`**; check `info.version` (`0.9.1`) in `/v3/api-docs`.

---

### 바뀐 것 | Changed

- **밤 정리가 빈 공간을 한 번에 더 많이, 묶어서 돌려줍니다.**
  - 한 번에 돌려주는 빈 페이지 몫이 5,000 에서 **20,000 페이지**입니다(페이지 크기가 4 KiB 인 DB 면 한 번에 최대
    약 78 MiB). 한 페이지씩 따로 처리하던 것을 250 페이지씩 묶어 처리하고, 묶음 사이에 50 ms 씩 쉬어 그사이
    들어오는 데이터 받기에 차례를 넘깁니다.
  - 회수 전에 확인하는 디스크 여유가 약 98 MiB 에서 **약 195 MiB** 로 늘었습니다. DB 가 있는 디스크의 남은 공간이
    그보다 적으면 그 밤의 회수를 건너뛰고 수집기 로그에 `free page reclaim skipped` 한 줄을 남깁니다. 보관 기간이
    지난 데이터를 지우는 정리 자체는 그대로 합니다.
  - 빈 공간이 많이 쌓인 날에는 [지난 데이터 정리] · [전체 삭제]의 응답이 몇 초 늦어질 수 있습니다. 묶음 사이에 쉬는
    시간만 합쳐도 약 4초입니다.

- **수집기 로그에 새 줄 셋이 생겼습니다**(모두 정보 줄). 기존 줄(`cleanup start:` · `reclaim start:` ·
  `reclaim done:` · `optimize advice:` · `optimize succeeded:`)의 문면은 그대로입니다.
  - `reclaim batches:` — `reclaim done:` 바로 다음 줄. 그 정리에서 처리한 묶음 수(`batches`) · 묶음 하나에 부탁한
    페이지 수(`batchPages`) · 묶음 하나가 가장 길게 걸린 밀리초(`maxBatchMs`)입니다. `maxBatchMs` 에는 연결을 얻고
    쓰기 차례를 기다린 시간도 들어 있습니다.
  - `wal checkpoint:` — 정리 끝에 WAL 을 비우는 체크포인트가 걸린 밀리초와 결과 값 셋(`busy` · `walFrames` ·
    `checkpointedFrames`). [최적화] 때도 남습니다.
  - `trace points superseded:` — 아래 대표 점 조회 차례 변경으로 밀려난 조회 하나마다 한 줄. 대표 점 조회가 낸
    `503` 을 셀 때는 `trace points busy:` 줄과 이 줄을 더하세요.

- **대표 점 조회(`GET /v1/trace-points`)를 여럿이 기다리면 가장 늦게 들어온 조회가 차례를 씁니다.** 먼저 기다리던
  조회는 차례가 와도 돌지 않고 `503` 을 받습니다(본문은 바쁨 `503` 과 같습니다). 화면에서 범위를 여러 번 바꿀 때
  지난 범위의 조회가 차례를 차지하지 않게 하려는 것입니다. 「한 번에 하나만」 규칙과 기다리는 한도(2초)는 그대로입니다.

- **형식이 안 맞는 인자에 대한 `400` 본문이 정해진 문장이 됐습니다.** 대표 점 조회와 목록 조회(`GET /v1/traces`)는
  숫자가 아닌 시각 · 모르는 `status` 값 · 숫자가 아닌 `limit` 같은 인자에 `{"error":"invalid parameter value"}` 로
  답합니다. 보낸 값과 서버 내부 이름을 더는 되비추지 않습니다.

- **설치 마법사가 거절할 때 서버가 돌려주는 이유 문장(`error`)이 한국어로 바뀌었습니다.** 화면의 「서버가 거절한
  이유:」 줄에 그대로 보입니다. 응답 모양과 거절 조건은 그대로입니다.

- **빨간 오류 알림 상자의 바탕이 더 진한 빨강으로 바뀌어 흰 글자가 또렷해졌습니다.** 설치 마법사 입력 칸 아래 빨간
  오류 글자도 같은 진한 빨강입니다. 차트 아래 시각 글자와 왼쪽 ms 글자도 조금 더 진한 회색입니다.

- 문서: `docs/setup.md` 는 server jar 가 agent jar 를 **실행할 때마다** `~/.apilens/` 에 풀어 둔다고 바로잡고, 같은
  기계에서 서버를 하나 더 띄울 때 그 자리를 바꾸는 법을 더했습니다. `docs/api.md` 는 대표 점 조회의 차례 규칙과
  빈 공간 회수 설명 한 문장을 바로잡았습니다.

- **버전 0.9.0 → 0.9.1** (collector jar · agent jar).

### 고친 것 | Fixed

- **차트에서 마우스를 한 점에서 다른 점으로 곧장 옮기면 말풍선이 앞 점의 내용을 들고 있던 것을 고쳤습니다**
  (v0.8.0 부터 있던 동작). 이제 말풍선 내용 · 가로세로 안내선 · 말풍선 상자가 늘 마우스 밑의 점을 함께 가리키고,
  점에서 빈 곳으로 벗어나면 함께 꺼집니다. 말풍선 상자는 마우스를 가리지 않는 쪽에 뜹니다.

- **operation 이름이 길면 말풍선에서 세 줄까지만 보이고 나머지는 줄여 보입니다.** 이름이 수백 글자여도 말풍선
  상자가 차트 밖으로 길어지지 않습니다. 전체 이름은 아래 목록과 상세 화면에 그대로 있습니다.

### 보안 | Security

- **경로 첫 부분에 세미콜론(`;`)을 붙인 조회 요청이 API 키 검사를 건너뛰던 결함을 고쳤습니다.** API 키를 설정한
  설치에서 토큰 없이 조회 API 와 저장된 요청 · 응답 본문을 읽을 수 있었습니다. v0.9.0 에도 있던 결함입니다. 이제
  경로에 세미콜론이 든 요청도 토큰 검사를 거칩니다(토큰이 없으면 `401`).

- 형식이 안 맞는 인자에 대한 `400` 본문이 보낸 값과 서버 내부 이름(타입 · 패키지 이름)을 되비추던 것을 대표 점
  조회와 목록 조회에서 고쳤습니다. 다른 조회 경로는 아래 「알려진 한계」를 보세요.

### 이렇게 보여도 정상 | Looks odd, but expected

- **점 위에 마우스를 가만히 두면**, 점이 흘러 나가며 말풍선이 꺼지고 다른 점이 밑으로 흘러 들어와도 다시 켜지지
  않습니다. 마우스를 조금 움직이면 그 점의 말풍선이 뜹니다.
- **다른 창에 완전히 가려져 있던 브라우저 창을 앞으로 가져오면**, 차트가 잠깐 멈춰 있던 것처럼 보이다가 한 번에
  지금 시각으로 건너뛸 수 있습니다. 가려진 동안 브라우저가 그리기를 줄이기 때문이며 정상입니다. 다른 탭에 있다가
  돌아올 때도 같습니다.
- **빨간 알림 상자와 설치 마법사 칸 아래 빨간 오류 글자만** 전보다 진해졌습니다. 차트의 오류 점 · 흐름 그림의 빨간
  테두리와 선 · 데이터 관리 화면의 빨간 단추는 그대로입니다. 차트 축은 글자만 진해졌고 축 선은 그대로입니다.
- **설치 마법사 화면에서 한국어 거절 이유를 볼 일은 거의 없습니다.** 잘못된 주소 · 이름은 화면 검사가 서버와 같은
  기준으로 먼저 막습니다.
- **서비스 목록의 agent 버전이 이전 라벨 그대로입니다.** agent 를 다시 배포하지 않았다는 뜻입니다.

### 알려진 한계 | Known limitations

- **형식이 안 맞는 인자에 정해진 문장으로 답하는 것은 대표 점 조회와 목록 조회뿐입니다.** 다른 조회 경로는 형식이
  안 맞을 때 아직 서버의 값 변환 오류 문장을 그대로 돌려줄 수 있습니다.
- **밤 정리의 회수 묶음이 그 시각 들어오는 데이터 받기와 겹칠 때 얼마나 걸리는지는 실제 운영 데이터로 아직 재지
  않았습니다.** 수집기 로그 `reclaim batches:` 줄의 `maxBatchMs` 로 그 밤에 묶음 하나가 가장 길게 걸린 시간을 볼
  수 있습니다.
- **대표 점 조회는 여전히 서버 전체에서 한 번에 하나만 돕니다.** 24시간 · 7일 같은 긴 창을 여러 탭에서 함께 보면
  「서버가 바빠 …」가 보일 수 있습니다. 도는 질의를 도중에 끊지는 못합니다.

### 업그레이드 | Upgrade

1. **수집기를 정상 종료합니다.**
2. **collector jar 를 교체하고 재기동합니다.** 이 버전은 **DB 스키마를 바꾸지 않습니다** — 기동할 때 하는 일이
   없습니다. 백업은 평소 습관대로 떠 두면 좋지만, 이번 버전을 올리기 위해 반드시 필요한 단계는 아닙니다.
3. **agent 는 다시 배포하지 않아도 됩니다** — agent 코드가 바뀌지 않았습니다. 그대로 두면 agent 버전 라벨이 이전
   라벨 그대로 보입니다. 라벨을 `0.9.1` 로 맞추고 싶으면 새 agent jar 로 바꾸고 대상 앱을 재시작하세요.
4. **열려 있던 브라우저 탭은 새로고침하세요.** 화면 왼쪽 위 라벨은 `v0.9` 그대로라, 새 화면인지는 말풍선 · 알림
   색으로 알 수 있습니다. 판은 `/v3/api-docs` 의 `info.version` 이 정확합니다.
5. **새 설정 항목이 없습니다** — 설정 파일이나 JVM 옵션을 손댈 필요가 없습니다. DB 가 있는 디스크의 남은 공간이
   약 195 MiB 보다 적으면 밤 회수가 건너뛰어진다는 점만 확인하세요.

- **되돌릴 때**: **jar 만 이전 버전으로 바꾸면 됩니다.** 스키마와 저장 형태가 그대로라 백업을 복원할 필요가 없습니다.
- **API 호환** — 경로 · 요청 · 응답에서 삭제되거나 타입이 바뀐 필드가 **0** 입니다. 오류 응답은 `{ "error": "…" }`
  한 키 모양 그대로이고, 바뀐 것은 일부 문장(글자)뿐입니다.

> **Collector and UI maintenance release — agent redeploy optional, no database migration, no breaking change.** The
> nightly cleanup now returns free pages in batches of 250 pages with a 50 ms pause between batches, and its per-night
> share grows from 5,000 to 20,000 pages (at most about 78 MiB per night for a database with 4 KiB pages). The free-disk
> check before reclaiming grows from about 98 MiB to about 195 MiB; if there is less free space, that night's reclaim is
> skipped with a `free page reclaim skipped` log line (the retention cleanup itself still runs). On days with a lot of
> free space, [지난 데이터 정리] (cleanup) and [전체 삭제] (purge) may answer a few seconds later — the pauses alone add
> up to about 4 seconds. Three new info log lines were added without changing the existing quoted ones:
> `reclaim batches:` (batches, pages per batch, longest batch in ms including the wait for a connection and the write
> lock), `wal checkpoint:` (checkpoint time and its three result values) and `trace points superseded:`. When several
> chart point queries wait, the newest one now takes the turn and the older waiting ones get `503` (same body as the busy
> `503`); count both `trace points busy:` and `trace points superseded:` lines for those `503`s. The point and list
> queries answer badly formatted parameters with the fixed sentence `invalid parameter value` and no longer echo the
> value or internal type names; other query paths may still return the conversion message. The setup wizard's rejection
> reasons from the server are now in Korean. The red error toast background and the setup field error text use a darker
> red, and the chart axis labels a darker grey. Fixed: on the chart, the tooltip, the crosshair and the tooltip box now
> always follow the point under the mouse, even when the mouse jumps straight from one point to another (present since
> v0.8.0); a long operation name now shows at most three lines in the tooltip, so the box stays inside the chart (the
> full name stays in the list and the detail view). Expected: a still pointer does not reopen the tooltip when another
> point flows under it; a window that was fully covered (or a background tab) may jump straight to the current time when
> you bring it back; the agent version label stays as before until you redeploy the agent. Known limits: how long a
> reclaim batch takes when it overlaps live ingest has not been measured on production data yet (see `maxBatchMs`). API
> paths, request and response fields keep their names and types. Rolling back is just swapping the jar. Security:
> requests whose path starts with a segment carrying a semicolon (;) skipped the API key check — fixed (also present in
> v0.9.0).
