## ApiLens v0.10.0 — Spring Boot 4.1 판올림 · agent 안 Jackson 고침판 | Spring Boot 4.1 upgrade and a patched Jackson inside the agent

**collector(server)를 Spring Boot 4.1 로 올린 판입니다.** 서버가 쓰는 Spring Framework 7.0 · Tomcat 11.0 · Hibernate 7.4 ·
Flyway 12.4 · SQLite 드라이버 3.53.4.0 이 모두 새 지원 라인입니다. **agent 도 다시 배포하세요** — agent 코드는 그대로지만
안에 든 Jackson 이 2.18.12 로 바뀌었고, 새 agent jar 로 바꾸고 대상 앱을 재시작해야 그 고침이 대상 앱에 닿습니다.
차례는 **collector 먼저, agent 나중**입니다. 다시 배포하지 않은 agent 도 새 collector 로 그대로 보낼 수 있습니다.

**DB 스키마는 바뀌지 않습니다** — 마이그레이션이 없어, 되돌리려면 이전 jar 로 바꾸기만 하면 됩니다. **하위호환을 깨는
변경도 없습니다.** 화면 왼쪽 위 버전 라벨이 **`v0.10`** 으로 바뀝니다.

**This release moves the collector (server) to Spring Boot 4.1** — Spring Framework 7.0, Tomcat 11.0, Hibernate 7.4,
Flyway 12.4 and the SQLite driver 3.53.4.0 are all on supported lines now. **Please redeploy the agent as well**: its
code is unchanged, but the Jackson bundled inside it is now 2.18.12, and the fix only reaches your application after you
swap in the new agent jar and restart the application. Upgrade **the collector first, then the agent**. Agents you have
not redeployed keep sending to the new collector. **No database migration and no breaking change** — rolling back is
just swapping the jar. The version label in the top-left corner becomes **`v0.10`**.

---

### 바뀐 것 | Changed

- **서버 지원 라인 전환.** Spring Boot 3.4.1 → 4.1.2 · Spring Framework 7.0 · Tomcat 11.0 · Hibernate 7.4 · Flyway 12.4 ·
  SQLite 드라이버 3.53.4.0 · springdoc 2.7 → 3.2. API 경로 · 요청 · 응답 모양은 그대로이고, `/v3/api-docs` 문서도
  OpenAPI 3.0 꼴 그대로입니다.
- **서버 JSON 처리는 Jackson 3 가 맡습니다.** 마스킹 엔진만 agent 와 같은 Jackson 2 라인을 씁니다. 그래서 Jackson 2 는
  두 판이 함께 쓰입니다 — 서버(마스킹 엔진) 2.21.7 · agent 2.18.12. agent 쪽은 agent jar 안에 relocate 돼 있어 서로
  부딪히지 않고, 저장되는 값은 서버가 마스킹한 결과입니다.
- **실패 모드 변경.** `POST /v1/spans` 의 JSON 본문(`Content-Type: application/json`)이 숫자 칸에 `null` 을 넣었거나
  올바른 JSON 뒤에 글자가 더 붙어 있으면, 전에는 `202` 로 받았지만 이제 `400` 으로 거절합니다. agent 는 이런 본문을
  만들지 않습니다. YAML 본문은 이 변경 밖입니다(아래 「알려진 한계」).
- **수집기를 Java 21 ~ 27 에서 띄울 수 있습니다.** 컴파일 대상은 Java 21 그대로이고, CI 는 그 양 끝인 21 과 27 에서
  시험합니다.
- **agent 안의 Jackson 을 2.18.2 → 2.18.12 로 올렸습니다**(relocate 된 채 들어 있어 대상 앱의 Jackson 과 부딪히지
  않습니다).
- **빌드 도구** — Gradle wrapper 를 8.11.1 → 8.14.6 으로 올렸습니다. Gradle 9 는 agent jar 안 구성이 달라지는 문제가
  있어 이번에는 올리지 않았습니다.

### 보안 | Security

- 이번 판올림으로 Spring Framework · Spring Boot · Tomcat · Jackson · SQLite · logback 의 공지된 취약점 고침판 위로
  올라갔습니다. 공지별 영향 범위 · 고침판 · 이 제품에서의 성립 조건은 [`docs/security.md`](../docs/security.md) 에
  있습니다. 대조한 공지 가운데 이 제품에서 성립 조건이 갖춰진 것은 없었습니다.
- 화면을 직접 빌드하는 경우에만 해당합니다 — 화면 개발 도구 vite 6.4.2 에는 개발 서버 쪽 공지가 걸려 있습니다(같은 표).
  배포 jar 에는 빌드된 정적 파일만 들어가고 vite 는 들어가지 않습니다.
- CI 에 배포물 의존성 취약점 검사(`npm audit`) · 의존성 그래프 제출 · Dependabot 알림 설정 · Spring Boot 지원 기간 경고를
  더했습니다.

### 이렇게 보여도 정상 | Looks odd, but expected

- **기동 로그에 springdoc 의 `WARN` 두 줄이 새로 찍힙니다.** API 문서(`/v3/api-docs` · `/swagger-ui`)가 켜져 있다는
  안내입니다. 두 문서는 전부터 토큰 없이 열려 있었습니다(README 「현재 한계」의 인증 항목).
- **Spring Boot 기본 오류 본문의 `timestamp` 끝 표기가 `+00:00` 에서 `Z` 로 바뀝니다**(예: 받지 않는 `Content-Type`
  의 `415`). 같은 시각을 다르게 적은 것입니다. ApiLens 가 직접 만드는 `{ "error": "…" }` 본문은 그대로입니다.
- **서비스 목록의 agent 버전이 이전 라벨 그대로입니다.** agent 를 아직 다시 배포하지 않았다는 뜻입니다. 새 agent 로
  바꿨는데도 이전 라벨이면, 대상 앱이 뜰 때 collector 가 꺼져 있었던 경우입니다 — collector 가 떠 있는 것을 확인하고
  대상 앱을 한 번 더 재시작하세요.

### 알려진 한계 | Known limitations

- **`/v1/spans` 는 YAML 본문(`Content-Type: application/yaml`)도 받고, 이 입구는 JSON 보다 느슨하게 검사합니다.** 위
  「실패 모드 변경」의 `400` 이 YAML 본문에는 걸리지 않아, 숫자 칸의 `null` 이나 본문 뒤에 더 붙은 글자를 그대로
  `202` 로 받습니다. 이전 버전에도 같았습니다. agent 는 JSON 만 보냅니다.

### 업그레이드 | Upgrade

1. **수집기를 정상 종료합니다.**
2. **collector jar 를 `apilens-server-0.10.0.jar` 로 바꾸고 다시 띄웁니다.** Java 21 ~ 27 에서 뜹니다. 기동할 때 새 agent
   jar 가 `~/.apilens/` 에 풀립니다. 이 버전은 **DB 스키마를 바꾸지 않습니다** — 기동할 때 DB 에 하는 일이 없습니다.
3. **collector 가 떠 있는 것을 확인한 뒤**, 대상 앱의 `-javaagent:` 가 가리키는 agent jar 를 새 것으로 바꾸고 대상 앱을
   재시작합니다. 서비스 목록의 agent 버전이 `0.10.0` 으로 보이면 끝입니다.
4. **열려 있던 브라우저 탭은 새로고침하세요.** 화면 왼쪽 위 라벨이 `v0.10` 이면 새 화면입니다.
5. **새 설정 항목이 없습니다** — 설정 파일이나 JVM 옵션을 손댈 필요가 없습니다.

- **되돌릴 때**: collector jar 를 이전 버전으로 바꾸면 됩니다. 스키마와 저장 형태가 그대로라 백업을 복원할 필요가
  없습니다. agent 는 코드가 그대로라 보내는 내용의 모양이 같지만, 새 agent 와 이전 collector 의 조합은 따로 시험하지
  않았습니다 — collector 를 되돌릴 때는 agent 도 이전 jar 로 함께 돌리고 대상 앱을 재시작하는 편이 안전합니다.
- **API 호환** — 경로 · 요청 · 응답에서 삭제되거나 타입이 바뀐 필드가 **0** 입니다. 달라진 것은 위 「실패 모드 변경」의
  잘못된 JSON 본문뿐입니다.

> **Collector moves to Spring Boot 4.1, the agent gets a patched Jackson — no database migration, no breaking change.**
> Spring Boot 3.4.1 → 4.1.2 with Spring Framework 7.0, Tomcat 11.0, Hibernate 7.4, Flyway 12.4, the SQLite driver
> 3.53.4.0 and springdoc 2.7 → 3.2; API paths, requests and response shapes are unchanged and `/v3/api-docs` stays
> OpenAPI 3.0. Server-side JSON now runs on Jackson 3; only the masking engine keeps the Jackson 2 line the agent uses, so
> two Jackson 2 versions are in use — 2.21.7 in the server's masking engine and 2.18.12 inside the agent (relocated, so
> they never clash); stored values are the server's masking result. Failure-mode change: a `POST /v1/spans` JSON body
> (`Content-Type: application/json`) with `null` in a numeric field, or with extra characters after valid JSON, used to
> be accepted with `202` and is now rejected with `400`; the agent never produces such bodies. The collector runs on
> Java 21 to 27 (CI tests both ends, 21 and 27); the compile target stays Java 21. Jackson inside the agent moves from
> 2.18.2 to 2.18.12. The Gradle wrapper moves from 8.11.1 to 8.14.6; Gradle 9 is held back because it changes the layout
> inside the agent jar. Security: the upgrade puts the shipped components above the fixed versions for the published
> Spring Framework, Spring Boot, Tomcat, Jackson, SQLite and logback advisories — see `docs/security.md`; none of the
> checked advisories applies to ApiLens. If you build the UI yourself, the dev tool vite 6.4.2 has dev-server advisories
> (same table); vite is not part of the shipped jar. CI now runs `npm audit` on production dependencies, submits the
> dependency graph, adds a Dependabot alert configuration and warns before the Spring Boot support line ends. Expected: two new
> springdoc `WARN` lines at startup (the API docs were already open without a token); Spring Boot's default error body
> writes `timestamp` with `Z` instead of `+00:00`; the agent version label stays as before until you redeploy the agent
> (if it still shows the old label after redeploying, the collector was down when the application started — restart the
> application once more). Known limit: `/v1/spans` also accepts YAML bodies (`Content-Type: application/yaml`), which are
> checked less strictly than JSON and still get `202` for the cases above, as in earlier versions; the agent only sends
> JSON. Upgrade: stop the collector, start `apilens-server-0.10.0.jar`, then — with the collector up — point
> `-javaagent:` at the new agent jar and restart your application. To roll back, swap the collector jar back; the
> combination of a new agent with an older collector was not tested, so roll the agent back together with it.
