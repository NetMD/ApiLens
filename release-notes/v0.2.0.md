## ApiLens v0.2.0 — 성능 수습 + 설정 페이지 + trace 필터 | Performance, settings page, trace filter

대용량 DB 에서의 성능을 수습하고, 보관 기간·마스킹 룰을 관리하는 **설정 페이지**와 대시보드
**trace 필터**를 추가했습니다. **agent 모듈은 변경 없음** (v0.1 agent 그대로 호환).

Performance fixes for large databases, plus a **settings page** (retention + masking rules) and a
dashboard **trace filter**. The agent is unchanged.

---

### ⚠️ 주의 (BREAKING) | Breaking

- **`GET /v1/services` 의 `traceCount` 의미 변경 — 누적 전수 → 최근 24시간** (`start_time` 기준). 누적 카운트가 대용량 DB 에서 매 호출 풀스캔을 유발해 윈도우 한정으로 바꿨습니다. 필드명·응답 구조는 무변경(UI 라벨 `Trace 수 (24h)`). 누적 카운트로 소비하던 외부 스크립트는 의미 재해석 필요.
- **retention cleanup 이 실제로 동작 시작 — 기본 30일 초과 trace 자동 영구 삭제**. v0.1 의 retention 설정은 dead key 라 무한 보관됐지만, v0.2.0 부터 매일 04:00 에 보관 기간(기본 30일) 초과 trace 가 영구 삭제됩니다(복구 불가). **30일 넘은 trace 를 보존하려면 업그레이드 후 첫 04:00 전에 설정 페이지(`/settings`)에서 보관 기간을 늘려 두세요**(1~3650일).
- **SQLite `journal_mode` 가 `delete` → `WAL` 로 전환** — DB 옆에 `-wal`/`-shm` 동반 파일이 생기고, 한 번 WAL 로 전환된 DB 는 v0.1 jar 로 롤백해도 WAL 이 유지됩니다(동작 문제 없음). `auto_vacuum=INCREMENTAL` 전환을 위해 첫 기동 시 1회 `VACUUM` 이 수행됩니다(DB 크기 비례 1회성 지연, 2회차부터 건너뜀).

### 새로운 기능 | What's new

- **설정 페이지 (`/settings`)** — 보관 기간(retention) 변경 + 마스킹 룰 관리 UI.
- **마스킹 룰 관리 API** (`/v1/masking-rules` — 목록/추가/삭제/토글 + 라이브 프리뷰) — 빌트인 default 룰 4종(주민번호/카드번호/password/token)은 그대로이며 관리 동작이 추가됐습니다. default 룰은 삭제 불가(409), 비활성 토글만 가능. 프리뷰는 agent/server 와 같은 공유 마스킹 엔진으로 계산합니다.
- **룰 핫 리로드** — 룰 변경이 서버 재기동 없이 적용됩니다(이후 ingest 분에만 적용 — 기존 저장 payload 재마스킹 없음). 기동 시 룰 로드 실패는 기동을 차단(마스킹 없는 침묵 기동 방지), 운영 중 reload 실패는 기존 룰을 유지합니다.
- **설정 API** (`GET/PUT /v1/settings`) — `retention.days`(1~3650, 원자 적용). 설정 페이지 저장 값(DB)이 yml 보다 우선, 미설정 시 yml fallback(기본 30일).
- **retention cleanup 스케줄러** — 매일 04:00, `payloads → spans → traces` 순 행 단위 배치 삭제.
- **Dashboard trace 필터** — status + operation 검색(`GET /v1/traces?q=` — root operation 풀 FQCN 부분 일치).

### 변경 | Changed

- **ingest 저장을 batchUpdate 로 전환** — 단건 INSERT 루프 제거(수신 batch 당 왕복 감소). 저장 결과 동일.
- **SQLite 운영 설정 적용** — `journal_mode=WAL` / `synchronous=NORMAL` / `busy_timeout=5000` 을 JDBC URL 로 적용 + 조회 인덱스 1종 추가(`traces(service_name, start_time DESC, trace_id DESC)`).
