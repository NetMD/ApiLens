## ApiLens v0.9.0 — 고른 시간 범위 전체를 그리는 대시보드 차트 | A dashboard chart that covers the whole selected range

**collector(server) 와 화면이 바뀌는 릴리스입니다. agent 코드는 바뀌지 않아 다시 배포하지 않아도 됩니다.** 지금까지
대시보드 차트는 그 창의 최근 100건(Live 1·5·10분 창은 500건)만 그려서, 요청이 많은 창에서는 점이 오른쪽 끝에만
몰렸습니다. 이제 서버가 고른 시간 범위를 시간 칸으로 나눠 **시간 칸마다 대표 점**을 골라 보내고, 차트는 창
전체를 그립니다. operation 검색어가 서버로 전달되지 않던 결함을 고쳤고, 밤 정리는 빈 공간이 많이 쌓인 날
[최적화]를 권합니다.

**DB 스키마는 바뀌지 않습니다** — 마이그레이션이 없어, 되돌리려면 이전 jar 로 바꾸기만 하면 됩니다. 백업을
복원할 필요가 없습니다. **하위호환을 깨는 변경도 없습니다.** 화면 왼쪽 위 버전 라벨이 **`v0.9`** 로 바뀝니다.

**This release changes the collector (server) and its web UI. The agent code is unchanged, so redeploying it is optional.**
Until now the dashboard chart drew only the latest 100 traces of the window (500 on the Live 1-, 5- and 10-minute
windows), so busy windows had all their points piled up at the right edge. The server now splits the selected range into
time buckets and sends **representative points per bucket**, and the chart covers the whole window. The operation search
text now actually reaches the server, and the nightly cleanup recommends [Optimize] on days with a lot of free space.
**No database migration and no breaking change** — rolling back is just swapping the jar. The version label in the
top-left corner now reads **`v0.9`**.

### 새로운 기능 | What's new

- **대시보드 차트가 고른 시간 범위 전체를 그립니다.** 차트의 점은 시간 칸마다 **오류가 아닌 요청 중 가장 느린
  하나**와 **오류**입니다 — 대표 점이라 전부가 아닙니다.
  - 차트 아래 범례 줄에 「전체 N건 중 M점」과 이 규칙이 늘 나옵니다. 오류가 아주 많아 줄여 보낸 응답이면
    「오류 X건 중 Y점만」이 진하게 나옵니다.
  - 점에 마우스를 올리면 그 점이 대표하는 시간 칸의 전체 건수와 오류 건수가 함께 나옵니다(창 가장자리 칸은 생략).
  - 서버가 바빠 차트 점을 못 받으면 오류 화면 대신 직전 점을 그대로 두고 범례 줄에 「서버가 바빠 …」로 알린 뒤,
    잠시 뒤 다시 불러옵니다.
  - Live 를 켠 24시간·7일 창은 차트 점을 30초마다 다시 받습니다. 아래 목록은 그대로 5초마다입니다.

- **차트가 쓰는 대표 점 조회(`GET /v1/trace-points`)가 생겼습니다.** 서비스 · 창의 시작 · 끝은 꼭 보내야 하고,
  창은 최대 7일(+ 10초 여유)입니다. 시간 칸의 크기는 서버가 창 길이로 고릅니다.
  - 창 안 오류가 500건을 넘으면 **오류가 있던 시간 칸마다 가장 느린 오류 하나**로 줄여 보내고, 줄였다는 표시를
    함께 싣습니다. 시간 칸마다 전체 건수와 오류 건수는 늘 다 실립니다. 「최근 몇 건」으로 자르지 않습니다.
  - 이 조회는 서버 전체에서 **한 번에 하나만** 돕니다. 이미 도는 중이면 최대 2초 기다렸다가, 그래도 바쁘면 `503`
    으로 답합니다. 큰 창 조회가 수집기의 데이터 받기를 밀어내지 않게 하려는 것입니다.
  - 자세한 내용은 `docs/api.md` 의 「대시보드 차트의 대표 점」 절에 있습니다.

- **밤 정리가 [최적화]를 권합니다.** 밤 정리가 지우기 직전에 본 빈 공간이 DB 의 25% 이상이고 100 MiB 이상이면,
  설정 「데이터 관리」의 최적화 칸에 권고 상자가 뜹니다.
  - 같은 판정이 수집기 로그에 `optimize advice:` 한 줄로 날마다 남고, 유지보수 상태 응답 맨 뒤의
    `optimizeAdvised` 에도 실립니다. 판정 줄은 권고가 뜨는 밤에도 경고가 아니라 정보 줄입니다.
  - [최적화]가 성공하면 권고는 곧바로 사라집니다. [보관 기간 즉시 적용]은 권고를 바꾸지 않습니다.
  - 권고는 어떤 단추도 막지 않습니다.

### 바뀐 것 | Changed

- 대시보드 목록 머리가 「최근 10건」 꼴로 바뀌었습니다(범례의 「전체 N건」과 섞이지 않게). 시간 범위 단추 글자에서
  「Last」를 뺐습니다(`1 min` … `7 days`).
- 창이 좁으면 대시보드 헤더가 두 줄로 접혀, 조작 단추가 화면 밖으로 나가지 않습니다. 차트 오른쪽 끝 눈금 글자가
  잘리지 않게 여백을 넓혔습니다.
- 차트를 누른 채 다른 창·다른 탭으로 가거나 오른쪽 클릭 메뉴를 열어도 흐름이 멈춘 채 남지 않습니다(왼쪽 단추로
  누를 때만 붙잡습니다).
- [차트 일시 정지]의 안내 문구가 「다시 누르면 지금 시각으로 돌아가 그동안 들어온 요청을 포함해 다시 그려요」로
  바뀌었습니다. 차트가 대표 점만 그리므로 「모두 보여 준다」는 말이 맞지 않아서입니다.
- 유지보수 상태 응답(`GET /v1/maintenance/status` · `POST .../pause` · `POST .../resume`) 맨 뒤에 `optimizeAdvised`
  필드가 붙었습니다. 기존 필드의 이름·타입·순서는 그대로입니다.
- 수집기 로그에 새 줄이 생겼습니다. 기존 줄(`sql statement gc start:` · `scan:` · `skipped:` · 요약 줄 ·
  `cleanup start:`)의 문면은 바뀌지 않았습니다.
  - `sql statement gc validate:` — SQL 원문 회수가 형식 검사에 쓴 시간.
  - `optimize succeeded:` — [최적화] 성공과 그때 권고를 거뒀는지(`adviceCleared`).
  - `trace points slow:` · `trace points busy:` — 대표 점 질의가 1초 이상 걸렸을 때 · 바빠서 `503` 으로 답했을 때.
    바쁨 줄은 `503` 마다 한 줄이라 긴 창을 여러 탭에서 함께 보면 자주 남을 수 있습니다.
  - 겹침을 알아채고 멈춘 회차의 줄(`sql statement gc folded:`)에도 회전 줄과 같은 이름·같은 뜻의 세 구간이
    붙습니다.
- **버전 0.8.0 → 0.9.0** (collector jar · agent jar).

### 고친 것 | Fixed

- **operation 검색어가 서버로 전달되지 않던 결함을 고쳤습니다.** 이제 검색어가 차트와 아래 목록에 함께
  걸립니다. 주소에 검색어가 남아 있던 탭은 결과가 줄어 보이는 것이 정상입니다.
- Live 를 켠 채 토큰 오류(401)를 받으면 「토큰이 필요해요」 안내가 다른 화면에 가려지던 것을 고쳤습니다.

### 이렇게 보여도 정상 | Looks odd, but expected

- **24시간·7일 창은 점이 거의 다 slow(노란) 색입니다.** 시간 칸이 길어 칸마다 가장 느린 요청을 고르기 때문입니다.
  색보다 높이로 읽어 주세요.
- **보관 기간보다 긴 창은 보관 기간 밖 구간(왼쪽)이 비어 있습니다.** 그 시간에 수신이 있었어도 이미 지워진 구간입니다.
- **주소에 검색어가 남아 있던 탭은 결과가 갑자기 줄어 보입니다.** 검색이 이제 실제로 걸리는 것입니다.
- **[최적화] 권고는 수집기를 다시 띄운 뒤 첫 밤 정리 전까지 안 보입니다.** 판정은 서버 메모리에 있고 밤 정리가
  하루 한 번 내립니다. 빈 공간이 적은 설치에서는 계속 안 보이는 것이 정상입니다.
- **시간 범위 · 서비스 · 필터를 바꾼 직후** 차트에 옛 점이 잠깐 남고 범례의 안내 문구만 잠깐 빕니다. 그동안
  [차트 일시 정지]는 눌러도 아무 일이 없습니다. 새 응답이 오면 돌아옵니다.
- **범례 줄 뒤쪽이 잠깐 「서버가 바빠 …」로 바뀌었다 돌아옵니다.** 그동안 흐르는 창은 잠깐 섰다가 앞으로 툭
  따라잡습니다. 뒤로 가지는 않습니다.
- **목록 머리 「최근 10건」은 범례 「전체 N건」보다 훨씬 작습니다.** 목록은 창의 최근 10건만 그립니다. 말풍선의
  시간 칸 건수도 그 칸 하나의 수라, 창 전체의 N 과 다릅니다(시간 칸 건수를 다 더하면 N 입니다).
- **창이 좁으면 헤더가 두 줄**입니다. 범위 단추에는 「Last」가 없습니다.
- **오래 걸린 요청의 점은 처음 낮게 보였다가 끝난 뒤 위로 올라가거나, 안쪽에서 늦게 나타날 수 있습니다.**
  v0.8.0 과 같은 동작입니다.
- **Live 를 끈 차트에서는** 한 칸 넘긴 직후 그 칸에서 늦게 끝난 요청이 빠지거나 짧게 보일 수 있습니다. Live 를
  켜거나 범위를 다시 고르면 보입니다.
- **서비스 목록의 agent 버전이 `0.8.0` 그대로입니다.** agent 를 다시 배포하지 않았다는 뜻입니다.

### 알려진 한계 | Known limitations

- **대표 점은 전부가 아닙니다.** 차트에 점으로 안 찍힌 요청은 아래 목록과 검색으로 찾으세요. 창의 정확한 건수는
  범례의 「전체 N건」과 말풍선의 시간 칸 건수입니다.
- **차트 점 조회는 서버 전체에서 한 번에 하나만 돕니다.** 24시간·7일 같은 긴 창을 여러 탭에서 함께 보면
  「서버가 바빠 …」가 자주 보일 수 있습니다. 도는 질의를 도중에 끊지는 못합니다.
- **데이터가 많은 설치에서는 7일 창 조회가 1초를 넘을 수 있습니다.** 그 조회가 밤 정리(기본 04:00)와 겹치면, 그
  조회 시간만큼 데이터 받기가 늦어질 수 있습니다. 개발 중 합성 데이터(30일 보관 꼴 · 약 545만 건 · 2026-10-05
  측정)로 잰 값은 7일 창 조회 약 1.3초 · 겹칠 때 데이터 받기가 가장 길게 기다린 시간 약 1.2초입니다. 수집기 로그에
  `trace points slow:` 줄이 날마다 보이면 이 경우입니다.
- **오류가 아주 많은 창에서는 한 응답의 점이 최대 1,462개까지 늘 수 있습니다**(서버 상한). 지금까지 차트가
  한 번에 그리던 최대 500건보다 많고, 그 상태에서 차트가 끊김 없이 흐르는지는 실제 브라우저에서 아직 재지
  않았습니다.
- **1분 Live 창에서 마우스를 한 점에서 다른 점으로 곧장 옮기면 말풍선이 앞 점의 내용을 들고 있을 수 있습니다.**
  v0.8.0 부터 있던 동작입니다. 마우스를 조금 더 움직이면 바뀝니다.
- 자동 API 스펙(`/swagger-ui`)에는 같은 묶음의 다른 조회 경로(목록 · 상세 · payload · 서비스 목록)에도 `503` 이 함께
  표시됩니다. 실제로 바쁨 `503` 을 내는 것은 대표 점 조회뿐입니다.

### 업그레이드 | Upgrade

1. **수집기를 정상 종료합니다.**
2. **collector jar 를 교체하고 재기동합니다.** 이 버전은 **DB 스키마를 바꾸지 않습니다** — 기동할 때 하는 일이
   없습니다. 백업은 평소 습관대로 떠 두면 좋지만, 이번 버전을 올리기 위해 반드시 필요한 단계는 아닙니다.
3. **agent 는 다시 배포하지 않아도 됩니다** — agent 코드가 바뀌지 않았습니다. 그대로 두면 agent 버전 라벨이
   `0.8.0` 으로 계속 보입니다. 라벨을 `0.9.0` 으로 맞추고 싶으면 새 agent jar 로 바꾸고 대상 앱을 재시작하세요.
4. **열려 있던 브라우저 탭은 새로고침하세요.** 옛 탭은 `v0.8` 라벨과 옛 차트를 계속 보여 줍니다.
5. **새 설정 항목이 없습니다** — 설정 파일이나 JVM 옵션을 손댈 필요가 없습니다.

- **되돌릴 때**: **jar 만 이전 버전으로 바꾸면 됩니다.** 스키마와 저장 형태가 그대로라 백업을 복원할 필요가
  없습니다.
- **API 호환** — 경로 · 요청 · 응답에서 삭제되거나 타입이 바뀐 필드가 **0** 입니다. 늘어난 것은 새 조회 경로 하나
  (`GET /v1/trace-points`)와 유지보수 상태 응답 끝의 필드 하나(`optimizeAdvised`)입니다.

> **Collector and UI release — agent redeploy optional, no database migration, no breaking change.** The dashboard chart
> now covers the whole selected range: the server splits the window into time buckets and sends, per bucket, the slowest
> non-error trace plus the errors (a new endpoint, `GET /v1/trace-points`). When a window has more than 500 errors, it
> keeps the slowest error per bucket and flags the response as reduced; per-bucket totals and error counts are always
> included. The legend row under the chart always shows "N traces, M points" and the rule; the tooltip adds the bucket's
> counts. The query runs one at a time across the server — it waits up to 2 seconds, then answers `503`, and the chart
> keeps the previous points with a "server busy" note. With Live on, the 24-hour and 7-day windows refresh their points
> every 30 seconds (the list stays at 5 seconds). The operation search text now reaches the server and filters both the
> chart and the list, so a tab that still had a search term in its URL will show fewer results — that is expected. A Live
> 401 no longer hides the "token needed" message. The nightly cleanup now recommends [Optimize] when the free space it
> saw before deleting is at least 25% of the database and at least 100 MiB: a box appears in Settings → Data management,
> an `optimize advice:` info line is logged every night, and the maintenance status responses gain a trailing
> `optimizeAdvised` field. The advice lives in memory, so it stays off after a restart until the next nightly run. Other
> changes: the list header reads "최근 N건" (latest N), the range buttons drop "Last", the header wraps on narrow windows,
> the chart keeps the right-most tick label inside, pressing the chart only holds the flow with the left button, and new
> log lines (`sql statement gc validate:`, `optimize succeeded:`, `trace points slow:`, `trace points busy:`) were added
> without changing the existing quoted lines. Expected oddities: long windows are mostly yellow (slowest per bucket),
> windows longer than the retention period are empty on the left, and the agent version stays `0.8.0` until you redeploy
> it. Known limits: representative points are not all traces; on large installs a 7-day query can exceed one second and,
> if it overlaps the nightly cleanup, delay ingest by that long (synthetic 30-day data measured on 2026-10-05: about 1.3 s
> per query, about 1.2 s longest ingest wait); a response can carry up to 1,462 points during an error storm, and how
> smoothly the chart scrolls at that size has not been measured in a real browser yet; on the 1-minute Live window the
> tooltip can keep the previous point's content when the mouse jumps straight to another point (present since v0.8.0).
> API paths, request and response fields keep their names and types. Rolling back is just swapping the jar.
