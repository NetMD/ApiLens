## ApiLens v0.11.0 — 외부 호출 구간이 그래프 끝에 보입니다 | Outbound HTTP calls now show up at the end of the graph

**앱이 바깥 HTTP 서버를 부른 구간이 노드 그래프의 주황 노드로 보입니다.** 메서드 · 호스트:포트 · 경로 ·
상태 코드가 노드와 상세 카드에 나오고, 4xx · 5xx 와 연결 실패 · 시간 초과는 빨간 테와 오류 상자로 보입니다.
Spring Framework 6.2 · 7.0 의 RestClient · RestTemplate 이 쓰는 Spring 내장 요청 구현을 계측합니다.

**agent 와 collector(server)를 둘 다 다시 배포하세요.** 차례는 **collector 먼저, agent 나중**입니다 — 새 agent jar 로
바꾼 뒤 대상 앱을 재시작해야 외부 호출 구간이 기록됩니다. 다시 배포하지 않은 agent 도 새 collector 로 그대로 보낼 수
있고, 그때는 외부 호출 구간만 안 보입니다. **DB 스키마는 바뀌지 않습니다** — 되돌리려면 이전 jar 로 바꾸기만 하면
됩니다. **하위호환을 깨는 변경도 없습니다.** 화면 왼쪽 위 버전 라벨이 **`v0.11`** 으로 바뀝니다.

**Outbound HTTP calls made by your application now appear as orange nodes in the trace graph** — method, host:port,
path and status code, with 4xx/5xx responses, connection failures and timeouts drawn as errors. The agent instruments the
built-in Spring request implementation used by RestClient and RestTemplate on Spring Framework 6.2 and 7.0. **Please
redeploy both the agent and the collector** — collector first, then swap the agent jar and restart your application.
Agents you have not redeployed keep sending to the new collector; only the outbound calls are missing. **No database
migration and no breaking change.** The version label in the top-left corner becomes **`v0.11`**.

---

### 새로 된 것 | Added

- **외부 호출 구간.** 앱이 바깥 HTTP 서버를 부르고 **응답 머리(상태 코드)를 받기까지**를 한 구간으로 기록합니다.
  - 들어오는 요청 안에서 부르면 그 흐름의 자식 노드로, 그래프의 오른쪽 끝에 붙습니다.
  - 요청 밖(예약 작업 · 별도 스레드)에서 부르면 그 호출 하나가 흐름의 시작점이 됩니다. 목록에는 그 호출의
    메서드 · 호스트가 든 이름으로 보입니다.
  - 노드 아래 줄과 상세 카드의 HTTP 묶음에 메서드 · 호스트:포트 · 경로 · 상태 코드가 나옵니다.
  - 쿼리 · 프래그먼트 · URL 의 사용자 정보와 요청 · 응답 본문은 저장하지 않습니다. **경로는 그대로 보입니다** —
    경로에 넣은 값(경로 매개변수 포함)은 마스킹을 거치지 않습니다.
  - 새로 쓰는 span 속성 키는 `server.address` · `server.port` 둘입니다(나머지는 기존 `http.*` 키 그대로).
    자세한 내용은 `docs/otel-attributes.md` 에 있습니다.

### 바뀐 것 | Changed

- **상세 화면 머리글** — 긴 이름이 한 줄로 줄고, 마우스를 올리면 전체가 보입니다. 외부 호출 하나뿐인 흐름은
  메서드 · 호스트:포트 · 경로로 보입니다.
- **선택한 노드 카드** — 머리에 마우스를 올리면 전체 이름이 보입니다. 오류 상자에 예외 타입 줄이 메시지 위에 따로
  붙습니다(모든 종류의 오류 카드에 같은 줄이 생깁니다).
- **계측 분석 화면** — 이름이 하나뿐인 계측 행의 이름이 「DB 접근 (전체)」에서 「DB 접근 · 외부 호출 (전체)」로
  바뀝니다. 외부 호출 기록도 클래스 이름이 없어 이 행에 함께 셉니다.
- **버전 0.10.0 → 0.11.0** (collector jar · agent jar · 화면 라벨 `v0.11`).
- 서버 코드와 서버 · agent 의 의존성 판은 바뀌지 않았습니다. 그래서 보안 공지 대조표(`docs/security.md`)의 부품 판도
  그대로입니다.

### 이렇게 보여도 정상 | Looks odd, but expected

- **외부 호출 노드의 본문 칸이 「(no request body)」로 보입니다.** 외부 호출의 본문은 저장하지 않습니다.
- **응답 머리를 기다리다 시간이 초과된 호출은, 앱 로그의 예외 원인(`Caused by`)과 상세 화면의 오류 스택에 agent
  프레임(`io.apilens.agent…`)이 함께 찍힐 수 있습니다.** 원인은 상대 서버이고, agent 는 응답 머리를 먼저 읽은
  자리일 뿐입니다. 드물게, 응답 머리를 기다리다 실패한 예외가 실행 시간 예외였으면 앱이 받는 예외가
  `java.lang.RuntimeException`(원인 = 원래 예외)으로 감싸질 수 있습니다.
- **서비스 목록의 agent 버전이 이전 라벨 그대로입니다.** agent 를 아직 다시 배포하지 않았다는 뜻입니다. 새 agent 로
  바꿨는데도 이전 라벨이면, 대상 앱이 뜰 때 collector 가 꺼져 있었던 경우입니다 — collector 가 떠 있는 것을
  확인하고 대상 앱을 한 번 더 재시작하세요.

### 현재 한계 | Known limitations

- **외부 호출의 시간 · 상태는 응답 머리(상태 코드)까지입니다. 본문 전송 지연과 본문 단계의 실패는 아직 반영되지 않습니다**
- **Spring 내장 요청 구현만 기록합니다.** JDK 내장 `HttpURLConnection` · `java.net.http.HttpClient` 를 직접 부르는
  코드, WebClient(reactor), OpenFeign 등 자체 HTTP 클라이언트, Spring 내장 구현을 따르지 않고 직접 만든 요청 구현은
  기록하지 않습니다. 지원 Spring 판은 6.2 · 7.0 입니다(자동 시험은 7.0 에서, 6.2 는 Spring Boot 3.4 앱에 붙여 실제로
  띄워 확인했습니다).
- **`@Async` 처럼 다른 스레드로 넘어간 작업의 외부 호출은 부모 흐름과 이어지지 않고 따로(단독 흐름) 기록됩니다.**
  진입점 없는 흐름을 만들지 않는 옵션(`apilens.instrument.require-entry-root`)을 켠 앱에서는 들어오는 요청 밖에서
  시작한 외부 호출을 기록하지 않습니다.
- **외부 호출 기록은 우리 앱 쪽 기록입니다.** 상대 서비스의 흐름과 잇지 않습니다 — 흐름을 잇는 요청 머리를 읽지도
  보내지도 않습니다.
- **응답을 읽지도 닫지도 않고 버리는 코드에서는 agent 가 응답 머리를 기다리는 만큼 그 호출이 늦어질 수 있습니다.**
  응답을 닫는 코드는 닫을 때 이미 머리를 기다리므로 새 대기가 없습니다.
- **바깥 시스템이 멈춰 외부 호출 오류가 한꺼번에 쌓이면, 대시보드 차트에서 들어온 요청의 오류가 덜 보일 수
  있습니다.** 오류가 아주 많은 창에서 차트는 시간 칸마다 가장 느린 오류 하나만 그립니다. 시간 초과로 끝난 외부 호출은
  대개 길어서 그 자리를 차지합니다. 그 오류들은 목록과 검색에는 그대로 있습니다. 검색에서 외부 호출만 빼는 거름은
  아직 없습니다.
- **외부 호출 기록을 끄려면** 대상 앱의 JVM 옵션에 `-Dapilens.instrument.exclude-packages=org.springframework.http.client.`
  를 더하고 대상 앱을 재시작하세요. 이 접두는 그 패키지의 계측 전부를 끕니다. 화면의 원격 계측 설정(개별 제외)으로는
  끌 수 없습니다.

### 업그레이드 | Upgrade

1. **수집기를 정상 종료합니다.**
2. **collector jar 를 `apilens-server-0.11.0.jar` 로 바꾸고 다시 띄웁니다.** 기동할 때 새 agent jar 가 `~/.apilens/` 에
   풀립니다. 이 버전은 **DB 스키마를 바꾸지 않습니다** — 기동할 때 DB 에 하는 일이 없습니다.
3. **collector 가 떠 있는 것을 확인한 뒤**, 대상 앱의 `-javaagent:` 가 가리키는 agent jar 를 새 것으로 바꾸고 대상 앱을
   재시작합니다. 서비스 목록의 agent 버전이 `0.11.0` 으로 보이면 끝입니다.
4. **열려 있던 브라우저 탭은 새로고침하세요.** 화면 왼쪽 위 라벨이 `v0.11` 이면 새 화면입니다.
5. **새 설정 항목이 없습니다** — 외부 호출 기록은 기본으로 켜지고, 끄는 길은 위 「현재 한계」의 기존 옵션입니다.

- **되돌릴 때**: collector jar 를 이전 버전으로 바꾸면 됩니다. 스키마와 저장 형태가 그대로라 백업을 복원할 필요가
  없습니다. 새 agent 와 이전 collector 의 조합은 따로 시험하지 않았습니다 — collector 를 되돌릴 때는 agent 도 이전 jar
  로 함께 돌리고 대상 앱을 재시작하는 편이 안전합니다.
- **API 호환** — 경로 · 요청 · 응답에서 삭제되거나 타입이 바뀐 필드가 **0** 입니다. 외부 호출 구간은 기존 span 의
  속성 안에 키가 더해지는 모양입니다.

> **Outbound HTTP calls become visible — no database migration, no breaking change.** The agent now records each call
> your application makes through the built-in Spring request implementation (RestClient, RestTemplate; Spring Framework
> 6.2 and 7.0 — automated tests run on 7.0, and 6.2 was checked by running a Spring Boot 3.4 application) from the
> request until the response headers (status code) arrive. Inside an incoming request the call becomes a child node at
> the right end of the graph; outside a request (scheduled jobs, separate threads) it becomes the start of its own trace.
> Query, fragment, user info and request/response bodies are not stored; the path is shown as is and is not masked. New
> span attribute keys: `server.address` and `server.port`. Changed: the trace detail header shortens long names to one
> line (hover for the full name), the selected-node card shows the full name on hover and an exception-type line in
> error boxes, and the single-name row in the instrumentation analysis is now "DB 접근 · 외부 호출 (전체)" because
> outbound calls also have no class name. Server code and dependency versions are unchanged. Expected: the body field of
> an outbound node shows "(no request body)"; on a response-header timeout the `Caused by` chain and the stack in the
> detail view may include an agent frame (`io.apilens.agent…`) — the cause is the remote server. Known limits: timing
> and status stop at the response headers; JDK `HttpURLConnection` / `java.net.http.HttpClient` called directly,
> WebClient, OpenFeign and other own HTTP clients are not recorded; calls on `@Async` threads are recorded as separate
> traces (and not at all when `apilens.instrument.require-entry-root` is on); outbound records are not linked to the
> remote service's traces; code that neither reads nor closes the response can be slowed by the time the agent waits
> for the headers; when a remote system stalls and outbound errors pile up, the dashboard chart (which keeps only the
> slowest error per time slot in very error-heavy windows) can hide errors of incoming requests — they stay in the
> list and search, and search cannot yet exclude outbound calls. To turn outbound recording off, add
> `-Dapilens.instrument.exclude-packages=org.springframework.http.client.` and restart the application. Upgrade: stop the
> collector, start `apilens-server-0.11.0.jar`, then — with the collector up — point `-javaagent:` at the new agent jar
> and restart your application. To roll back, swap the collector jar back; roll the agent back together with it.
